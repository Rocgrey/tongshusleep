# 睡眠日期切换性能优化 · 2026-11-15

## 原因

睡眠页收到真实 BIO 分期后，一晚同时展示阶段图和夜间体征。旧的体征视图分别为指标列表、均值、次数及图表筛选样本，每个样本又遍历整晚阶段，并在内层反复读取 SwiftData 属性。切换日期会重复执行这些计算。

时间标签每次创建 DateFormatter；页面还会提前构建屏幕外内容，图表跨日期复用身份，需要处理两晚之间的差异。此外，根界面的自动同步准备也会整理历史数据，其中每条体征的日期分组原来都会创建格式器。这是可能叠加的界面线程开销，不能将它直接认定为每次日期点击的原因。

## 修改

- 新增 `BIONightPresentation.swift`：样本和睡眠区间分别排序后单次扫描，按指标汇总均值、次数及图表样本。原始数据完整保留，不降低采样密度。
- `SleepModels.swift`：复用已有的非持久化缓存；按原始 metadata/segments 字节失效，刷新、替换阶段或改体征后重新计算。缓存记录日期和按记录时区配置的时间格式器，时区改变后更新。
- `BIONightView.swift`：一次读取汇总，供指标列表、数值和图表使用。睡眠记录只统计实际睡眠区间内的采样；无分期的夜间观测仍展示实际收到的观测。
- `SleepDashboardView.swift`：单次筛选来源、日期和索引；使用 LazyVStack 延后构建屏幕外内容；图表按记录 ID 区分，避免把两晚当作同一张图更新，也重置上一晚的交互状态。
- `DeviceStepsView.swift`：最近体征不再在过滤每条记录时重复读取全部可见样本。
- `AccountStepsModels.swift`：固定 UTC+8 的日期和时间格式器独立复用，不改变服务端日期口径、上传字段或严格日期校验。
- `SleepTongshuApp.swift`：仅增加明确启用的 UI 测试数据入口，普通运行不加载性能测试数据。

未变更数据库结构、持久化原始健康数据、账号归属、AIS 或上传契约；没有新增 ISI。缓存只存于当前进程，记录被释放后随之释放。

根界面的自动同步目前仍需生成历史上传请求和指纹。本次减少了其中的日期转换开销，没有重写同步调度；如果真机仍有周期性卡顿，应继续采样定位编码、蓝牙和界面线程占用。

## 验证

1. 单元测试覆盖清醒/缺失区间排除、结束边界、无分期观测、跨记录缓存隔离、元数据及阶段修改后失效、时区变化，以及密集样本与旧公式结果一致。
2. 日期测试覆盖 UTC+8 跨日、反复交替使用日期/时间格式，以及拒绝无效日期和非标准字符串。现有账号、步数、自动同步、本地 BIO 睡眠和系统睡眠测试一并运行：最终 190 项，跳过 1 项，失败 0 项。
3. 模拟器 SE 第三代界面测试通过三项：七晚密集测试记录往返切换日期并显示阶段图、小屏幕夜间体征图、大字体夜间体征图。截图已人工查看。测试记录明确标为“界面性能测试示例 · 非真实数据”。
4. 基准测试使用合成的 4,000 条体征、96 个阶段，五轮汇总：旧重复扫描约 1.89 秒，新缓存汇总约 0.014 秒。这只是一次模拟器上的计算对照，不代表整页帧率、真实夜晚样本量或真机切换耗时；测试不以这个时间作为通过条件。
5. 普通 iOS 工程和戒指工程均完成 iPhone 构建。优化版已安装到现有测试 iPhone；真实操作是否仍卡顿需用户在手机上确认，模拟器自动化不替代真机流畅度测量。

## 真机检查

进入“睡眠 → 设备记录”，连续切换上一晚/下一晚，再打开日期列表选择较早记录。分别在首页顶部和下滑查看阶段图、夜间体征后操作。收到新一轮设备数据后，再查看原日期的图表和均值是否更新。

请观察蓝牙正在同步及同步结束后两种情况。如果仍卡顿，需要记录发生时是否显示同步中、所选日期和卡顿位置，进一步进行真机性能采样。
