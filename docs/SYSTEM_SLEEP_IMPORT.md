# 系统睡眠读取与本地报告

本次在现有 SwiftUI、SwiftData、HealthKit 与图表上增量开发，保留手机监测、蓝牙设备同步、账号、AIS 与主动上传。不增加 ISI，不新增后端接口。

## 使用

1. 打开“健康”或“睡眠”，阅读“系统睡眠”中的本机处理用途说明，主动点击 **读取系统睡眠**。
2. 首次系统授权只申请 `sleepAnalysis` 读取，`toShare` 为空；不申请写入。此前已经请求过睡眠读取的用户，系统不一定再次弹出授权页。
3. 成功后显示最近读取时间、实际记录日期和段数；健康页读取会更新睡眠页并切到“系统健康”，不会用示例补空。
4. 睡眠页选择日期或左右切换可看每次睡眠；有真实分期时点击时间轴，查看阶段、开始、结束及时长。未分期时只显示真实睡眠总时长；仅卧床显示“仅有卧床记录”。
5. “趋势”选择系统健康来源，查看近 7/30 天日时长、有效日期日均，以及每次入睡/结束变化；午睡也保留。
6. 来源详情展示来源 App、可获得的设备字段、记录时区、原始样本 UUID。未提供设备信息就显示“来源未标明设备”，不推断品牌型号。

蓝牙连接不会自动生成系统健康睡眠。手机、手表或第三方设备的配套 App 必须支持并**实际写入 Apple 健康**，本 App 才能读取。

没有记录时统一提示：**未读取到睡眠记录，请检查系统健康中的数据和访问设置**。HealthKit 无法向本 App 区分“没有数据”和“未允许读取”，不把空结果判定成拒绝授权。

排查：健康 App → 浏览 → 睡眠 → 显示所有数据，先确认记录存在；再到头像 → App 与服务（部分系统为 App / 数据访问与设备）→ sleeptongshu，检查睡眠读取设置。可在 App 的信息按钮查看说明，不跳到空白页面。

## 读取、去重和归日

- 查询窗口从本地日历 90 天前的日开始到当前时刻。查询额外向前取 24 小时，防止切断窗口边缘的跨夜记录；最终按睡眠结束时刻筛选归属窗口。单条超过 24 小时或无效样本不参与整理。
- 使用范围重查，不使用 anchored query。上限 50,000 条；超过上限或查询失败时保留旧数据，不用不完整结果做删除对账。
- App 与可获得的设备身份共同组成来源键，保留真实 App 名称、bundle ID、设备字段、UUID 及样本时区。未知原始类别不补造阶段。
- 同一来源先按时序组成睡眠时段，超过 30 分钟没有任何睡眠/清醒记录时分开；缺口不补成睡眠或清醒。跨午夜不按自然日切段，同日多次睡眠与午睡分别保存。
- 同一来源的重复样本/同类重叠取时间并集。真实分期优先于同源未分期总区间；相互冲突的明确阶段记为“未记录”。卧床始终是背景，不和阶段相加。
- 每组实际重叠的时段优先采用真实 Core/深睡/REM 覆盖更长的完整来源，再比较实际睡眠覆盖时长；相同则用稳定来源键及开始时间决胜。**不把多个来源拼成完整分期**。相比旧的“每自然夜一条”，本次只在重叠时竞争，以保留不重叠的午睡。
- 只因一个较长的卧床区间重叠，不排除另一来源的真实午睡。一个卧床区间覆盖多次睡眠时，不把它拆成看似完整的效率分母。
- 时长使用绝对起止时间相减，正确跨越夏令时。日期取最后一段真实睡眠结束时、该段来源记录的时区；无时区元数据时使用读取时的系统时区并保存，不猜测原始时区。仅卧床取卧床结束日。日期标签与显示时区保存在元数据中，之后切换手机时区不改变这晚的归日。作息图线长按真实经过时间绘制，时钟调整日的本地时刻以详情为准。
- Core 在界面显示为浅睡；`asleepUnspecified` 显示“未分期睡眠”，不转为浅睡。无记录的阶段不展示或上传推算值。
- 清醒次数统计首次入睡后、最后一次睡着前明确的清醒段，不包括入睡前与最终起床；只有连续覆盖、且确有分期或清醒样本时才汇总。不从仅未分期的总时长推算清醒次数或清醒总时长。
- 效率 = 实际睡眠时长 / 同一来源完整卧床时长；只有卧床范围被睡眠/清醒连续覆盖、且卧床未因覆盖多个时段而拆分时才展示。没有卧床、阶段冲突或覆盖缺口就不计算。系统导入不生成自定义参考分。
- 趋势先按来源系列筛选，再按结束日合计不重叠的夜间和午睡时长；无记录不当作 0、不参与日均。旧版无区间的多来源快照沿用保守最大值，待新读取后替换，不直接相加。

## 本地保存

SwiftData 的 `SleepRecord` 仍沿用原有表结构，新字段保存在可选 `SleepMetadata.healthSleep` JSON 中；旧备份和其他来源数据可继续读取，不需要删除数据库。

导入以原始样本 UUID 生成稳定外部标识；重复读取更新已有对象。样本修改导致 UUID 改变时，按共同样本或重叠时段匹配旧导入，保留本地记录 ID 和独立备注。范围内旧导入没有出现在成功读取结果中，则标记归档；不会继续计入图表和统计。由于权限关闭和删除都可能导致空结果，这里只描述“系统中已不可见”，不声称确定已删除。归档可在“健康 → 健康设置 → 系统睡眠归档”查看，恢复访问后重新读取可恢复匹配的记录。

不覆盖手动、蓝牙、手机估算或示例记录，也不删除查询范围外的旧导入。SwiftData 和快照写入失败时回滚本次变更并保留旧记录。健康页与睡眠页共用 `HealthOverviewStore`，使用同一导入器，前台超过 15 分钟检查更新，失败重试至少间隔 60 秒；首次读取由用户点击发起。手动点击可刷新，读取期间按钮禁用。

读取和保存不触发任何上传。既有单条主动上传继续经 APIClient 鉴权，AIS 保留；新 JSON 不含 `isi_score`。系统睡眠不发送伪造的评分/缺失阶段。

真机操作：

1. 在 Xcode 选择自己的签名 Team，普通工程使用 `sleeptongshu.xcodeproj`；要保留已适配戒指 SDK 使用 `sleeptongshu-Ring.xcodeproj`。两者均需要支持 HealthKit 的描述文件；戒指 SDK 仅真机运行。
2. 先在健康 App 确认最近有睡眠，或在配套 App 完成向系统健康写入。开启本 App，点击“健康 → 读取系统睡眠”，在系统页面允许睡眠读取；不应出现健康写入项目。
3. 对照健康 App 的同一来源、同一晚，核对开始/结束、实际睡眠时长和阶段；切到“睡眠”应立即显示真实系统记录，并可看来源、样本标识和阶段详情。
4. 连续点两次读取，确认记录数量与时长不翻倍。记录已有睡前备注，再修改/删除一条测试睡眠，重新读取，检查本地更新或归档、备注保留。只操作自己特意创建的测试记录，勿删除需保留的个人记录。
5. 分别试有夜间和午睡、没有分期、仅卧床、没有记录的情况；空结果应显示统一说明，不自动换成示例。
6. 关闭读取权限再刷新，确认不宣称“已拒绝”、旧导入进入归档；重新开启并读取应恢复。检查深色、大字体和小屏幕滚动。
7. 未点击“上传这晚睡眠”时，不应产生系统健康睡眠的网络上报。
