# L03 戒指直接同步工程

2026-10-28 更新：当前版本为 **0.2.2**，用户界面移除品牌提示和“测试”标题，新增记忆设备、连接后自动同步、独立体征存储与图表。下文保留 0.2.1 的接入验证经过；操作与指标限制请以 [设备同步 0.2.2](DEVICE_SYNC_V022.md) 为准。现在无需点击旧测试按钮，重连也无需先搜索。

日期：2026-10-27。测试设备信息：协立 L03 Ultra，G Band，固件 `00.12.11.00-2511`。用户最终澄清：这是尚未使用的新戒指，还没有睡眠图；此前“G Band 已有数据”的回答不再作为设备已有记录的依据。

## 此次进展

根据用户提供的真实服务诊断，设备没有标准 `180F/180A/180D` 服务。当前普通版只能读标准特征，因此原先连接后没有电量、型号、心率，并不表示设备没有这些数据。

实际服务包括 `F0020001-0451-4000-B000-000000000000`，其中 `F0020002-0451-4000-B000-000000000000` 为通知特征，`F0020003-0451-4000-B000-000000000000` 可写；另有 `F003`、`F0080001-0451-4000-B000-000000000000`、`FEE7`。这些标识与核对的 Veepoo SDK 字符串吻合。

**已在这枚真实 L03 上确认连接和设备验证通过，SDK 历史读取流程结束。戒指报告睡眠类型 6，目前设备没有有效睡眠/体征记录；完整分期与逐晚数据一致性需要佩戴过夜后验收，不应标记为已验证睡眠兼容。**

## 在手机上测试

1. 先结束 G Band 正在进行的同步。不要解绑戒指，不需要恢复出厂设置。
2. 打开戒指测试版 sleeptongshu，在“监测与设备 → 穿戴设备”搜索并连接 `L03`。
3. 等待服务检查完成，在设备名称下方会出现“戒指睡眠同步 · 测试”和“读取戒指睡眠”主按钮。连接后不再显示无关扫描结果，标准特征与长诊断收纳到折叠项。点击主按钮才会开始厂商同步；“识别到戒指私有通道”本身只是服务检查结果。
4. App 先释放原来的标准连接，然后由 SDK 重新连接、验证设备、同步历史。连接验证最长等待 40 秒，历史传输最长等待 180 秒；可随时取消。设备时间会随 SDK 的验证流程校准，请保持 App 前台运行。
5. 读取完成后自动断开，将验证通过的睡眠保存到本机。在“睡眠”的日期/记录选择器及“趋势”的来源选择中查看戒指记录，并与 G Band 同一晚对照。
   新戒指没有历史时，显示“连接与验证成功，设备暂无可导入的睡眠记录”，不创建零时长或示例报告。先佩戴过夜，次日在 G Band 确认生成真实报告后，再测试本 App 的导入。
6. 如果失败，展开“戒指同步诊断”并复制或分享文字。报告区分连接、验证、传输、格式验证，包含厂商返回的记录数量和被拒绝数量，不包含原始睡眠曲线、体征值、设备密码或设备地址。报告也保存在 App 沙盒 `Documents/Diagnostics/veepoo-last-sync.txt`，采用文件保护，供调试读取；不自动上传。再次尝试前需重新搜索、连接戒指。

普通版仍可扫描和分享服务诊断，但没有链接厂商库；真实读取要使用这里的独立戒指工程。小米手环没有新增专用历史协议支持。

## 读取与数据处理

- 使用官方 `VPBleCentralManage` 的自扫描连接及验证回调，等待该 SDK 的蓝牙管理器 poweredOn 后才连接，避免刚初始化时误报“蓝牙未开启”；验证成功后串行调用 `veepooSdkStartReadDeviceAllDataWithReadStateChangeBlock:`。没有重放用户日志里的整段初始化命令，也没有调用清空设备、修改密码或固件升级接口。
- 基础同步完成后，设备声明支持血氧时调用 `veepooSdkStartReadDeviceOxygenData:`。该步骤最多等待 30 秒；无法完成时保留已取得的睡眠和其他可用体征，缺失值为空。它不保证 SDK 对这枚戒指开放全部血氧或呼吸功能。
- 睡眠类型选择遵循官方 Demo `VPTestSleepController`：类型 0/2 查询普通睡眠，其他类型（含真实戒指报告的 6）查询精准睡眠。普通睡眠按 SDK 文档中每字符 5 分钟的浅睡、深睡、清醒映射；精准睡眠使用 SDK 的 `parseSleepLine`，支持深睡、浅睡、REM、清醒，厂商“失眠”标记在时间轴按清醒展示。未识别分期和时间缺口保持“未记录”，不会补出深睡或 REM。类型 6 的真实曲线目前仍没有样本可验证。
- 相邻精准睡眠分段只有在连接标志匹配、时间连续时才拼接；不完整的跨段记录不作为完整睡眠保存。单段不超过 24 小时，未知曲线格式会拒绝。
- 心率读取 SDK 原始数据的 `heartValue` 字段；血氧/呼吸率取 SDK 返回的已定义字段。仅在记录的睡眠阶段内统计有效读数，排除清醒、未记录时段、零和 `255` 等无效值；同一时间冲突的体征不任意选取。没有直接把 PPG/ECG 数组推算为精确时间点。
- 稳定 ID 来自设备标识的哈希和睡眠起点；相同记录再次同步更新原记录，不重复新增。数据继续使用既有 `SleepPayload` / SwiftData，备份格式和模型未改变。
- App 不建立账号或上传服务。SDK 使用自己的本地数据库中转，导入后记录保存在 App 内；现有备份仅导出 App 睡眠记录，不包含 SDK 缓存。现有“清理记录”清理的是 App 报告，不能当作删除 SDK 全部内部缓存的保证。SDK 内部网络行为尚未完成审计，本测试版不承诺厂商库完全离线。

## 工程与依赖

独立工程为 `sleeptongshu-Ring.xcodeproj`，scheme 为 `sleeptongshu-Ring`，版本显示 `0.2.1`。它与普通工程共享 SwiftUI、图表、数据模型及新读取代码，使用同一 Bundle Identifier，可覆盖调试安装并保留原有 App 数据。不会自动卸载 App。Team 需为开发者自己的签名团队。

主工程原有的用户/Xcode 配置修改保留；独立工程将 SDK 的 iPhoneOS arm64 库与模拟器、Mac Catalyst 构建分开。主工程依然能用于普通调试、健康 scheme 与自动化测试。

SDK 来源：[HBandSDK/iOS_Ble_SDK](https://github.com/HBandSDK/iOS_Ble_SDK)，固定版本 `c1ec1363c659deaa483778315b86e680f8f81af0`，使用其 `2.2.XX.15` 目录及官方 Demo 配套依赖。依赖清单在 `Configuration/VeepooManifest.json`，下载的每个文件都核对 Git blob SHA-1；CDN 缓存只在内容与固定哈希一致时接受。

```sh
# 新检出后下载固定版本的依赖；本机已完成
/usr/bin/python3 scripts/setup-veepoo.py

export DEVELOPER_DIR="$HOME/Downloads/Xcode.app/Contents/Developer"
xcodebuild -project sleeptongshu-Ring.xcodeproj -scheme sleeptongshu-Ring \
  -destination 'generic/platform=iOS' -derivedDataPath work/RingBuild \
  CODE_SIGNING_ALLOWED=NO build
```

也可直接用 Xcode 打开戒指工程，选择自己的 Team 和已连接的 iPhone，再按 Run。此工程不能选择模拟器或 Mac Catalyst。源代码与固定清单进入 Git，下载的第三方库位于忽略的 `Vendor/Veepoo/`，未把用户日志或厂商二进制上传到本仓库。

`scripts/build-veepoo-support.sh` 编译 FMDB/MJExtension 支持库，链接官方依赖，并仅在 App 内嵌入需要的动态 framework。动态库裁剪为 arm64 并使用 App 当前签名身份签名。厂商与 FMDB/MJExtension 许可证一起放入测试 App 的 `VendorLicenses`。
