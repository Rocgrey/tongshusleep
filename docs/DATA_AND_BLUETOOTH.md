# 数据与蓝牙

## 记录与计算

`SleepRecord` 是 SwiftData 本地模型，`SleepPayload` 是独立的 Codable 值类型。

| 字段 | 内容 |
| --- | --- |
| `id` | UUID，导入去重标识 |
| `start` / `end` | 本条睡眠起止时间，支持跨午夜 |
| `source` | sample、manual、healthKit、band；后两者仅为预留来源 |
| `segments` | 按时间排列且首尾连续的 awake、rem、light、deep 时间段 |
| `heartSamples` | 有时间戳的心率点 |
| `averageHeartRate` | 可空，次/分 |
| `averageSpO2` | 可空，百分比 |
| `averageRespiratoryRate` | 可空，次/分 |
| `note` | 用户笔记 |

- 有阶段时，总睡眠是非清醒阶段时长之和；效率是总睡眠 / 起止时间窗口；深睡占比是深睡 / 总睡眠。
- 夜间清醒是起始阶段之后的清醒段数。样例生成器会生成连续分期，不把分段本身虚构为不同指标。
- 手动记录没有阶段，起止差值作为用户报告的睡眠时长；效率、分期比例、清醒次数和分数不显示。
- 参考分 = min(总睡眠分钟 / 480 × 100, 100) × 0.6 + 效率 × 0.4，结果四舍五入。该公式仅供个人观察。
- 趋势按记录结束日期筛选，7/30 天包括当天；没有数据的日期不填 0。若同一天录入多条，当前按多条记录展示，平均值也是记录平均值。

## 备份与服务器接口

JSON 顶层为 `version`（当前 1）、`exportedAt`、`records`。日期使用 ISO 8601。导入先整体校验，再批量保存；校验失败不会写入部分数据。已存在 UUID 保留本地版本，同批重复 UUID 也跳过。

校验：起止有效且不超过 24 小时；分期无重叠、间隙并覆盖全窗口；心率/血氧/呼吸率数值有限且处于宽泛的技术可接受范围；心率点位于窗口；笔记不超过 2000 字；文件不超过 10 MB。这些校验不是医学阈值判断。

未来 `SleepSyncClient` 使用值类型跨异步边界：

```swift
protocol SleepSyncClient: Sendable {
    func upload(_ records: [SleepPayload]) async throws
    func download(since: Date?) async throws -> [SleepPayload]
}
```

当前无网络实现、无账号、无 CloudKit。将来接入前应增加服务器协议、认证、版本冲突与删除同步语义。

## 蓝牙实现边界

`BandScanner` 仅在用户点击扫描后创建 `CBCentralManager`，系统此时才会请求蓝牙权限。扫描 12 秒自动结束；用户选择设备后连接超时为 15 秒；离开设备页停止扫描。

连接后只查询标准服务：电量 `180F / 2A19`，设备信息型号 `180A / 2A24`。这些特征不存在时保持空值。并未实现小米私有服务认证、加密握手、历史睡眠同步、后台采集、睡眠阶段解码或体征解码。

BLE 的本地 UUID 不是硬件序列号。设备名可被广播方任意设置，不能据此认定型号。iOS 模拟器不支持真实 BLE 扫描；Mac 的蓝牙结果也不能替代 iPhone 实测。

## 实机适配所需信息

先记录设备包装/设置中的准确型号、固件版本、iOS 版本与当前绑定状态。使用公开 SDK 或有依据的协议资料实现独立适配器，并用设备导出的数据比对时间戳、单位、夜间划分、阶段和缺失值。私有协议不稳定时，不应把连接状态显示为同步成功。
