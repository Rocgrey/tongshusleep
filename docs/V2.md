# 第二版 · 手机与穿戴双模式

版本 0.2.0，iOS 17 起。第一版代码保存在 Git 标签 `v0.1.0`，升级保持原 Bundle ID 和 SwiftData 存储位置。请先在“设备与数据”导出备份，不要卸载旧 App。新模型只增加可选元数据字段，旧记录和旧版 JSON（version 1）继续支持；新备份为 version 2。

## 在 iPhone 上试用

1. Xcode 打开 `sleeptongshu.xcodeproj`，选择普通 **sleeptongshu** scheme 和你的 iPhone，按运行按钮。
2. 打开底部“监测”，选择“手机监测”，打开“开启手机睡眠跟踪”。首次点击“开始今晚监测”时允许麦克风访问。权限被拒绝后，前往系统设置中的麦克风权限更改。
3. 手机放在床上靠近身体、不超过 50 厘米的位置，例如枕头旁。不要放在枕头下面，不要用被褥覆盖。床边硬桌上的手机不一定能感知床面动作。
4. 电量充足；充电时保持通风。建议保持 App 前台，可在控制中心调低亮度。监测期间 App 阻止自动息屏，结束后恢复原设置。
5. 早晨点击“结束本次监测”再“保存睡眠报告”，到“睡眠”查看。“报告示例”用于提前看图表，不会写入真实记录。

麦克风使用系统音频会话及后台 audio 模式。锁屏/后台不是整夜采集保证，系统可能限制体动回调；电话、其他录音、音频路由变化、系统终止、强制退出都可能中断。出现中断会结束本次采集，保留已收到的信号；不会为停止期间补造信号。每 30 秒原子保存本机草稿，异常退出最多可能损失最后一个检查点之后的数据。采集超过 23 小时自动停止。

短时间测试可以保存声音/体动报告，但可能无法估算睡眠，这是正常情况。模拟器不能代替整夜真机采集验证。

## 手机数据的含义

| 项目 | 方法与边界 |
| --- | --- |
| 声音 | 麦克风缓冲区计算 RMS，分钟平均 dBFS，是相对数字信号强度，不是经过校准的环境分贝 |
| 体动 | 加速度向量模长偏离 1g 的绝对值，保留每分钟最大值；同床者、宠物、移动手机都会影响结果 |
| 疑似鼾声/说话 | Apple SoundAnalysis version1 本机声音分类器，置信度不低于 75% 的窗口累计；1.5 秒窗口、50% 重叠，按 0.75 秒步长估算时长；不保存音频，也无法确定声音来自本人 |
| 估算入睡 | 连续 15 个相邻分钟窗口，声音采样至少 40 秒、平均低于 -35 dBFS 且体动小于 0.025g，取该串窗口的起点 |
| 估算时长 | 从上述起点之后满足相同安静规则的音频秒数合计除以 60；不是整段卧床时间，也不是生理睡眠分期 |
| 睡眠质量 | 目前提供声音、体动和时长观察与建议，不生成手机“医学睡眠质量分” |

这些阈值是未经过临床验证的初始规则。安静清醒可被误计为睡眠，打鼾睡眠可能被排除。没有足够信号、没有体动数据或没有连续窗口时，入睡与时长显示缺失，不填成 0 小时的睡眠，不参加时长平均。声音模型不可用时，不生成鼾声/说话统计；说话声不会直接写成梦话。手机无法测量深睡、REM、血氧、心率和呼吸率。

疑似声音统计是重叠窗口后的近似时长，不是独立“打鼾次数”，也不是呼吸暂停检测。睡眠阶段和体征必须来自实际设备记录，不能用于诊断。

## Apple 健康

为了保持现有个人签名的基础安装路径，普通 scheme 不带 HealthKit entitlement，入口会明确显示尚未启用。

启用方式：

1. 在 Xcode 顶部 scheme 菜单选择 **sleeptongshu-Health**。它使用 `Health` 配置及 `Configuration/HealthKit.xcconfig`，自动启用 HealthKit entitlement 和运行时开关。
2. 在项目主 target 的 Signing & Capabilities 中选择支持 HealthKit 的 Team，确保对应 App ID/描述文件允许 HealthKit。若个人免费 Team 被苹果拒绝，需使用支持此能力的开发者账号；普通 scheme 仍能继续测试手机采集。
3. 选择 iPhone 运行，在“监测”点击“连接 Apple 健康”，授权需要的数据项，选择一个来源/设备，再“导入所选来源”。App 只读取，不向健康写入。

命令行构建健康版本（无签名，仅检查编译）：

```sh
xcodebuild -project sleeptongshu.xcodeproj -scheme sleeptongshu-Health \
  -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO build
```

读取最近 30 天的已有数据，不会凭空使 iPhone 具备手环生理监测能力。必须先由 Apple Watch、设备厂商 App 或其他来源写入健康。Apple 不向 App 透露用户是否拒绝了读取，空结果可能是没有数据，也可能是未授权。

同一数据源/设备独立导入，按结束时间所在的“中午到次日中午”窗口归组；同一来源同一窗口用稳定 ID 更新。时间边界会受当前时区影响，跨时区重导入前请检查记录。午睡可能与当晚合并为同一窗口，缺口保留“未记录”，不能当作连续睡眠。

分期按照区间边界拆分；互相矛盾的阶段保留“未记录”，未分期睡眠单独标识，卧床样本不会直接变成睡眠。存在缺口时不生成效率、深睡占比及参考分等不可靠指标。体征仅使用对应来源/可识别设备、落在已记录睡眠阶段内的样本，取算术平均；没有就显示缺失，不借用其他设备体征。不做自动后台 HealthKit 同步，可再次手动导入更新。

## 穿戴设备

“监测 → 穿戴设备”和“设备与数据”共用同一蓝牙连接。支持 BLE 扫描、连接、标准电量/型号读取；设备有 180D / 2A37 标准服务时可订阅实时心率。实时心率不自动写成整夜睡眠平均。设备需要可被第三方发现/连接；经典蓝牙或封闭设备不一定适用。

任意设备的深睡、浅睡、REM、清醒与整夜体征并没有统一通用的 BLE 历史睡眠协议。当前没有实现小米、华为或睡眠戒指的专用历史同步。`WearableSleepAdapter` 作为后续厂商 SDK/协议的接入边界，不能把有接口说成已经支持硬件。可先使用设备到 Apple 健康的同步路径；厂商侧仍可能要求登录。

## 隐私与存储

- 原始声音只在内存中处理并丢弃，保存分钟窗口、分类统计和来源；本版没有声音回放功能。
- 手机草稿在 Application Support/PhoneMonitoring，采用原子写入和首次解锁后的文件保护；正式记录仍在原 SwiftData 存储。
- 删除报告、移除示例、全部清理在“设备与数据”；采集中草稿需要在“监测”单独结束/舍弃。导出正式备份不包含未保存草稿。
- 不建立 App 账号，不上传录音或健康数据，无 CloudKit。系统/iCloud 整机备份是否开启由你的 iPhone 设置决定。
- `SleepSyncClient` 继续作为未来服务器接口；当前没有服务器地址、API key 或上传任务。
- 趋势按记录来源/设备分开，默认选择最新的真实来源，没有真实记录时预览示例。

## 真机验收

仍需要你使用 iPhone 和实际设备验证：麦克风允许/拒绝、来电中断、锁屏与后台、8 小时耗电与温度、异常退出恢复、不同床面与摆放、旁人声音误识别；健康授权/撤销及真实记录来源；标准心率设备连接/断线/订阅。当前代码与模拟器测试不能证明鼾声分类准确率，也不能证明某个未测试的手环或戒指可读。
