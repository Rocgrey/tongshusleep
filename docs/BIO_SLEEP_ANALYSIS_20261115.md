- 按服务器地址和稳定用户 ID 检查采集归属；其他账号的已绑定采集不参与分析。没有修改原始报告或把别的设备补进来。

## 给 WorkBuddy 的配置要求

App 已使用现有接口，不需要另起服务或改路径。请在部署 `Rocgrey/sleep_tongshu_web` 的服务环境中完成：

1. 安全配置 `IWOWN_ALGORITHM_ACCOUNT` 和 `IWOWN_ALGORITHM_PASSWORD`，然后重启服务。使用厂家为该设备开放睡眠算法的正式凭证，不要把密码提交仓库、写进 App 或输出到日志；平台演示账号不保证具有该设备算法权限。
2. 保留 `POST /api/v1/health/bio-sleep-analysis` 的现有 JWT 校验和请求/响应契约。最新仓库 `app/api/v1/bio_algorithm.py` 已有环境变量读取和固定厂家接口代理。
3. 确认部署环境可访问 `https://api1.iwown.com/algoservice/calculation/sleep`。现有服务端发送 account/pwd(MD5) 请求头及厂家要求的 JSON 字段，不由 App 直接携带厂家凭证。
4. 用当前用户的真实分析请求联调：区分平台 503、厂家非零 `return_code`、成功但无有效 sections，以及真正成功。若返回 10403，请厂家确认这枚 BIO 的实际设备地址如何映射 `device_id`、绑定算法账号及服务权限；不要改用其他客户设备 ID。
5. 仅当 `return_code=0` 且 result 含合法 `completed/start_time/end_time/sections`，才作为成功。不能返回示例图或根据固定比例生成阶段。返回部署版本和去除敏感信息后的联调结果。

配置后：手机登录并开启自动同步，保持前台；服务问题至少间隔 5 分钟重试。收到有效结果后更新本机对应日期的睡眠记录，随后由既有健康同步流程上传到当前账号。也可以退出前台再进入或重新连接 BIO 检查新输入，退出/进入不会绕过已有重试间隔。
