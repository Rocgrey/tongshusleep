# BIO 夜间记录与自动同步

## 使用

1. 登录自己的账号，在“监测与设备”点击已记忆的 BIO 重连，保持前台等待读取结束。
2. 睡眠页默认优先展示设备记录，不需要点击“从系统健康读取”。日期选择器与设备记录列表包含 BIO 的夜间记录。
3. 有有效厂家分期时复用睡眠时间轴、深睡/浅睡/快速眼动、清醒次数与睡眠期间体征。只有原始输入时显示“夜间观测”：实际体征均值、采样次数、指标切换和散点图，不生成睡眠时长、分期、参考分。
4. 默认自动同步自己的真实睡眠、每日累计步数、设备体征到登录账号。页面显示同步进度或失败原因；“上传这晚睡眠”按钮已移除。在“健康 → 个人账号”可关闭“自动同步健康记录”。示例不上传。系统健康仍只申请读取权限；读取授权与服务器同步开关分别控制。
5. 自动同步在 App 前台有变化时及每 45 秒检查，网络失败至少间隔 30 秒重试。退出后停止，切换服务地址或账号时同步回执隔离。iOS 不保证 App 被关闭后仍能持续传输。

## 数据口径

- BIO9 / 103 固件历史时间按实测的 UTC+8 本地时钟编码转换；夜间观测窗口为前日 18:00 到结束日 12:00。12:00–18:00 的体征仍保存在体征记录及云端全天体征，不冒充夜间睡眠。
- 同一设备、同一结束日使用稳定 UUID；再次读取按原始体征 ID 合并，保存备注。分段读取缺少某个包不表示删除旧数据。多个目录重复包去重。
- 观测窗口不是入睡/起床时间。观测均值只代表有采样的时刻，不是已识别睡眠期间均值。图表不跨缺口连线。
- 厂家结果仅接受明确的深睡(3)、浅睡(4)、清醒(6)、快速眼动(7)。未知、越界和重叠结果拒绝；缺口保留“未记录”。非最终结果标为阶段性结果。
- 真正睡眠结果的体征均值只取睡着区间内的采样。清醒次数只统计两段睡眠之间的明确清醒段；缺少覆盖不展示效率/清醒汇总。睡眠效率沿用睡着时长÷整段完整记录时长，设备记录可能不含入睡前的卧床时间。
- 步数按每日累计覆盖，不能把新累计值加到旧值。同日云端汇总沿用 HealthKit > 穿戴 > 手机来源优先级，多个穿戴来源取最新有效累计，不把设备累计与系统汇总相加。真实 0 步与没有记录区分。

## 厂家云算法

对照厂家 calculation.html 的睡眠接口及 Java `SleepPreprocessor` / `RriPreprocessor` 实现：提交相邻两日按测量时间排列的 Q/T/P/H/V/E 字段，保留 RRI 的有符号 16 位编码及控制标记。它只是数据预处理，不是自行编写的分期算法。

App 通过自己的平台 `POST /api/v1/health/bio-sleep-analysis` 提交，厂商账号仅由服务端环境变量 `IWOWN_ALGORITHM_ACCOUNT` 和 `IWOWN_ALGORITHM_PASSWORD` 提供；不写入 App、仓库或日志。关闭自动同步也停止云算法调用。每份输入最多每 5 分钟重试。

本次公开文档示例请求返回 HTTP 200 / ReturnCode 10404；以旧 BIO 日志预处理输入实测返回 10403（设备未被确认归属），没有获得有效分期。旧报告只有本地设备哈希，不是厂家设备标识，不能据此断言该设备不支持。新版从设备信息响应保存实际 MAC，重连后再核验；仍需厂家确认其 `device_id` 格式、账号绑定及算法服务权限。文档平台演示账号不等于该设备已开通算法。

不采用示例 `/health/sleep` 的模拟结果，不用“无动作 15 分钟”等简单规则生成深睡/快速眼动。

## 自有平台新增契约

详细字段、部署和服务端测试见 Web 仓库 `docs/DEVICE_AUTO_SYNC.md`。

- `GET /api/v1/health/sync-capabilities`：必须声明 v1 幂等能力；旧部署缺少接口时 App 保留本地记录并提示，不回退到非幂等旧上传接口。
- `POST /api/v1/health/device-sync`：`record_key/kind/record_date/revision_at/device_id?/device_name?/sleep?/steps?/vitals/details`。kind 为 sleep、night_observation、steps、vitals。用户身份来自 JWT，不传 user_id。缺失字段省略，不发送 isi_score。
- 同一服务+用户+record_key 更新同一快照。App 先持久化版本再发送，超时使用原版本重试；服务器同版本同内容幂等，旧版本忽略，同版本不同内容 409。
- 真实睡眠投影至原睡眠表，保留 AIS；无分期观测不进入睡眠统计。详情保存阶段区间、时间口径、实际均值，体征保留采样时间和值。Web 可切换指标查看散点图。
- `GET /api/v1/health/device-records` 查询当前账号快照；管理员使用 `/api/v1/admin/users/{id}/device-records`。

## 验证和真机步骤

自动化覆盖：观测与真实睡眠区分、跨日归档、重复/部分读取、备注、未知设备、RRI 编码、厂家结果合法性、缺口、按睡眠区间计算均值、自动同步版本与重试、账号/服务隔离。界面使用明确标识的合成输入，验证小屏深色与大字体；不代表真机已返回分期。

本次结果：166 项 iOS 单元测试（1 项真机可选信号测试跳过）及相关 UI 测试通过；Web 14 项接口测试通过，1440/390 宽度验证图表非空、指标切换、无脚本错误及无整页横向溢出。普通模拟器工程及戒指真机工程构建成功。已覆盖安装并启动用户 iPhone，用户确认出现“夜间观测”。这只确认本地观测展示，不等于已取得厂家分期或线上上传成功。

2026-11-11 核对线上 OpenAPI 时尚无新同步/算法接口，需要部署本次 Web 更新后联调。部署后重新连接 BIO，检查电量、体征、夜间观测日期与自动同步状态；在同账号 Web 查看设备记录。佩戴一晚后同步，若厂家服务实际返回有效 sections，睡眠页会自动切换为阶段图；否则保留观测并显示原因。请勿通过删除 App 重装清空测试记录。
