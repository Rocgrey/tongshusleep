# BIO 连接后自动采集与上传（2026-11-12）

## 能收到什么

读取了厂家新增 PDF、Word、Excel、PPT 及睡眠输入 JSON 示例。资料混有不同型号及 4G 上传说明，不能把 R103 的压缩心电格式、采样率直接套到 BIO9 蓝牙数据。

本机 iPhone 的实际 BIO9 / 103.0.0.11 报告，经更新后的 Web 服务在本地验证：

| 数据 | 实际记录 | 解释 |
| --- | --- | --- |
| 实时 BIOZ（512） | 133 包、798 个值 | 生物电阻抗原始计数，保留负值和原通知字节 |
| 历史健康与睡眠输入（0） | 2870 包 | 含设备计算体征及 sleep_data 输入编码；并非睡眠分期 |
| 历史 RRI（4） | 134 包 | 心跳间隔编码字与设备时间；保留标记，不直接当作有效毫秒 |
| 历史心电（2） | 7 包 | 保留原计数及字节，单位和本型号采样说明待确认 |

这些数字是 11 月 11 日 19:40 那次已完成报告的实收数量，不是设备完整容量。实时 ACC（16）、PPG（2）、ECG（1）尚待新版逐类请求的真机结果；历史 PPG、血氧独立通道、温度、转动和加速度在该报告被拒绝，不能据此认定其他健康包里也没有血氧。

实时类型与历史通道是两个命名空间，例如实时 2=PPG、历史 2=ECG，不能混用。

已从手机保存的服务端回执确认：这 139 包分 100/39 两批接收，此前 130/133 包也已接收；一份 3011 个历史包的完整报告已由平台接收。该报告在线旧解码器回执 decoded_rri=0，需 Web 部署本次 HisData 修复；本地新解码器已验证 134 个 RRI 包。线上“已收到”与“已正确解码”分开记录。

## 新版 App 行为

1. 连接并确认 BIO 型号/固件后自动请求 ACC、PPG、ECG、BIOZ，每类约 5 秒，逐类停止再切换，不再需要单次采集开关。只订阅原始信号，不远程打开诊断测量模式。
2. 实时包每类最多 256 包、总计最多 1024 包/100000 个值；原始采集完成就分批入本机队列，不等待历史读取或云算法返回。当前仍是约 20 秒的连接验证，**不是整夜连续采样**。
3. 继续原有历史读取；结束或中断后把完整接入报告冻结入队，包括原始 Protobuf JSON/Base64、通道状态、电量、设备标识和型号。无数据也保留报告，便于区分未返回、空目录和拒绝。
4. 登录且开启个人页自动同步时，通过统一 APIClient / JWT 自动上传；前台每 15 秒检查队列，断网保留本机文件重试。实时和报告使用相同 capture_id，报告键为 `probe|capture_id`。成功回执核对用户、稳定键和数量后保存，重传不会新增。
5. 连接时已登录的采集绑定服务地址和稳定用户 ID。退出或换账号后不向另一账号传送该采集；未登录时或升级前无归属的本机采集在首次同步时绑定账号。升级会补传最近一份已完成 BIO 报告及此前待传实时批次。

接口沿用后端 main `5198356` 的实际契约：`POST health/raw-sensor-batches` 和 `POST health/probe-reports`。报告字段 camelCase 保持原样，不新增另一套历史上传路径。读取权限本身不触发自动上传，仍受账号自动同步设置控制。

## Web 改动与查看

修复 `HisData` 直接消息与外层 `HisNotification` 的兼容。RRI、ECG、PPG、睡眠输入的 fixed32 数组按厂家 .proto 解析，原始字节不改；类型/序号不匹配时保留原文并标为未确认，不把数组标为解析成功。已有 v1 包原位重解析，保留主键、账号、原文和回执，不另插数据。历史睡眠输入图明确写为算法输入，不是睡眠阶段。

网页登录同一账号 → **信号浏览** → 选择 BIO 采集会话。实时和历史按类型分组；会话可标为“实时与历史”。每页 200 包，支持翻页，列表前 60 包可点开，其余可填包 ID 查看；单包可下载 JSON、二进制、CSV。候选 16 位拆分只对 RRI 提供；其余数据不套用该编码。

本地真实报告预览：`http://127.0.0.1:8767/`。预览使用独立本机测试账号，不是线上账号，不代表线上已经接收。

## 厂家资料的作用与限制

- 《4G数据说明最新》明确睡眠分析需要前一天和当天的数据；REM、睡眠呼吸率和睡眠心率需 RRI。PPG、原始加速度历史数据注明可能需定制。
- 《睡眠计算公式》是已有睡眠结果的得分规则，输入是时长、深睡占比和清醒时长，**不是原始信号到分期的算法**。
- 《RRI画图方法》讲相邻正值画散点，不能因此删除原文中的负值标记或直接进行分期。
- `有睡眠的数据示例.txt` 包含 390/234 条两日分钟输入、两组各 13860 个 RRI 编码值，日期 20240903；是厂家示例，不作为用户真实睡眠记录。
- 文档中其他客户的账号不用于自动登录或算法调用。原始采集成功不代表厂商云算法的设备归属问题已经解决。
