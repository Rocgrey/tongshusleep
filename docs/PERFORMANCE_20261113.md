# 2026-11-13 流畅度优化

## 发现与修改

- BIO 收到每个原始包/历史包时都会修改发布的报告，反复复制增长中的数组并重绘进度和图表。现在先缓存收到的包，每 250 毫秒合并发布；采集结束、通道检查点和断开时立即清空缓冲。原有包数、数值和字节上限及去重规则保留。
- 自动上传此前每 15 秒在 MainActor 上读取、解码全部待传文件，并在其后才检查回执。现在由独立 actor 串行处理文件、报告恢复、体征解码和请求编码，缓存不可变队列文件的少量元数据，已确认上传的文件不重复解码。回执键、服务地址与账号归属规则、JWT 和重试路径不变。
- 睡眠图表和各指标反复读取同一份 JSON 编码的分期、心率和夜间体征。现在每份本地记录在内存缓存解析结果，编码字段变化时立即重新解析；缓存不存入数据库，不改变持久化字段，不需要删除原记录。直接字段更新、替换、清空和坏数据后的恢复均有验证。
- 步数监听先过滤无步数的报告、去除完全相同的日累计结果，避免原始包进度触发无关的步数处理。
- 异步恢复或解码结束后检查对应采集身份，旧读取结果不能覆盖新连接。

## 验证

- 普通工程单元测试 176 项，跳过 1 项，无失败。
- 3011 包合成历史报告约 5.9 MB，后台队列读取、请求编码和完整原文往返校验通过；未确认上传可重试，确认后跳过文件解码，切换服务/账号隔离通过。
- 模拟器对含 4000 条体征的一晚记录连续读取 40 次：原直接 JSON 解析约 0.323 秒，缓存读取约 0.008 秒（含首次解析）。这是局部测试，不是整款 App 的帧率或真机速度承诺。
- 紧凑屏幕的原始信号图、夜间观测图两项 UI 测试通过，使用明确标注的合成数据。
- 戒指工程真机目标构建通过，已覆盖安装至连接的 iPhone，启动后进程正常运行。
- 本轮尚未测量真机持续蓝牙采集时的掉帧率，也未重新完成一整轮 BIO 真机上传验证。需要使用者比较连接 BIO 时滚动、四个底部页面切换、睡眠日期切换的实际手感。

## 主要文件

- `sleeptongshu/WearableProbeClient.swift`：收包缓冲、合并发布、后台检查点和恢复。
- `sleeptongshu/WearableProbeReport.swift`：后台串行工作 actor。
- `sleeptongshu/RawSensorData.swift`：后台上传队列、回执过滤、元数据缓存和请求编码。
- `sleeptongshu/SleepModels.swift`：记录字段解析缓存及失效。
- `sleeptongshu/SleepTongshuApp.swift`：步数监听去重。
- `sleeptongshuTests/RawSensorTests.swift`、`sleeptongshuTests/SleepRecordTests.swift`：队列、账号隔离、大报告和缓存一致性验证。
