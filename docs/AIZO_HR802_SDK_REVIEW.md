# HR802 戒指 SDK 文档核对

日期：2026-11-04。用户提供设备为 HR802，固件 9.12.15，配套 App 为 AIZO RING。本次审阅用户提供的两份 PDF，包含代码截图；未把 PDF 当成可链接的 SDK，也没有对这枚戒指完成实际数据读取。

## 结论

**存在读取候选原始数据的明确入口：iOS 文档第 24～26 页提供 PPI 接收、解析与本地保存流程。它值得进一步测试，但不能据此保证当前固件能提供可用于自主睡眠分期的整夜信号。**

PPI 通常指相邻脉搏的时间间隔，比单个心率或一晚 HRV 数值更接近算法需要的输入。不过本文档没有完整给出返回数组结构、单位、无效标记、时间对齐或整夜覆盖保证，也不能把 PPI 当成连续原始脉搏波。

当前电脑中找到的是文档及日志，没有找到 `RingSDK.framework`、对应依赖、头文件或完整 Demo。0.2.8 不会假装接入这个缺失的 SDK，也不对 HR802 猜测并发送私有命令；原有戒指和手表测试路径保留。

补充日志核对：厂家 App 日志已出现健康与浅睡、深睡、清醒、快速眼动结果，但本次固件功能输出的 `isSupportEmotion` 为 0，尚未证实原始 PPI 成功返回。情绪日志的 0 条是本地上传队列状态，不能单独证明硬件不支持。详见[2026-11-04 日志分析](DEVICE_LOG_REVIEW_20261104.md)。

## 能否自己计算睡眠阶段

1. **展示已有睡眠**：若正式 SDK 与固件匹配，可先读取厂商阶段与清醒次数，核对原配 App，明确标注数据来源。
2. **重新计数清醒**：可根据已返回的阶段转换计数，但这是对厂商分期结果的统计，不是独立识别。未佩戴、缺口及关机不能当清醒；入睡前的清醒段也不计为夜间醒来。
3. **自主识别睡眠与清醒**：需要证明能拿到连续的身体活动信号及时间信息。单有间歇 PPI 或分钟心率无法保证识别静卧清醒。
4. **自主深睡、浅睡、快速眼动**：PPI 可作为候选特征之一。还需连续性、信号质量、有效标记、时间对齐及适用的训练/验证数据，通常应有整夜睡眠检查的对照分期。不能把“情绪功能已授权”当作睡眠算法已验证。

PDF 没有确认开放原始光学脉搏波、连续三轴加速度的 iOS 方法、单位及采样率，也没有提供可直接移植的独立睡眠分期算法。后续应先收集完整夜间数据，分别评估静止、活动、松动、未佩戴和缺失情况，再决定算法。

## 接入仍需厂家提供

- 与 HR802 / 固件 9.12.15 对应的完整 iOS SDK、依赖、头文件和可运行 Demo，尤其是 `OriginalDataTestController`、`EmoDataModel`、`BTOriginalDataManager`、`BTOriginalDataPacket`。
- 原始数据 `dataType` 的完整枚举，PPI 数组格式、单位、时间戳时区、无效值、排序、去重和一包覆盖时间；历史保存天数及可否整夜连续获取。
- PPI、光学脉搏波、三轴加速度分别支持哪些硬件与固件；采样率、量程、压缩/滤波和信号质量标志。
- 功能授权是否需要开发密钥或联网，数据采集与本地解析是否能完全离线，避免默认调用云算法。
- 绑定及连接的正式流程与数据影响。文档提到充电座、解绑和系统忽略设备，本轮没有执行这些操作，不自动解绑或复位用户设备。
- SDK 的使用/分发许可。PDF 不会随代码提交到公开 GitHub，用户提供的蓝牙地址和健康日志也不会公开。

拿到 SDK 后，优先做“能力查询 → 历史健康/睡眠串行同步 → 限时 PPI 验证 → 本地导出”，保留原始包及解析数组；不先接云算法，也不将未知数据补成睡眠阶段。
