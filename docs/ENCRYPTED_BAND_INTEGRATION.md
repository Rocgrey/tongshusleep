# 加密手环接入测试

日期：2026-11-11。

## 范围和当前状态

在现有蓝牙列表中识别 FE95 / 005E / 005F 通道。首次导入已有设备绑定凭证，保存在独立 Keychain 项；后续通过已连接设备记录直接重连并自动认证和读取。不要求在本 App 输入厂商账号密码，不实现云端登录或首次绑定绕过。

实现参考 [cobanov/freeband](https://github.com/cobanov/freeband)，固定核对提交 `f677838def2c3dcfc24d0929de492e391d977f14`。协议、加密、文件分包和解析代码经重命名与适配后编入两个现有工程；MIT 声明随 App 包含于 `FREEBAND-NOTICE.txt`。没有引入上游的 AGPL 测试素材、字体、云端或评分代码。`STBand` 文件保留上游协议结构与注释，App 的数据保存及界面由本工程实现。

这是待真机验证的接入实现。上游作者报告 Band 10 Pro 的认证与文件读取可用，但不能据此宣称本用户的 10 Pro NFC 已兼容。用户目前反馈 iPhone 文件中没有配套 App 文件夹，尚未取得设备凭证。本次未完成该手环的真实认证、运动或睡眠读取。

## 真机操作

1. 保留原有手环绑定，不解绑、不恢复出厂设置。结束配套 App 正在进行的蓝牙同步。
2. sleeptongshu → 监测与设备 → 设备检测 → 搜索蓝牙，选实际设备名称。若此前连接过，可直接点已连接设备。
3. 识别到兼容加密通道后，点“导入设备绑定凭证”。只连接蓝牙尚未代表认证通过。
4. 如“文件 → 我的 iPhone”实际提供配套 App 文件夹，主动选择该文件夹，再从读取结果中选择对应设备。否则只能输入用户已经持有的 32 位十六进制设备凭证；它不是账号密码。没有凭证就保留提示，不制作假成功。凭证不要通过聊天或公开仓库分享。
5. 保存后自动释放原扫描连接，再连接同一蓝牙标识、完成设备 HMAC 认证并读取历史。约两分钟的文件同步窗口，保持 App 前台与设备靠近。部分文件超时会单独重试；断开时保留已收到的有效文件。
6. 对照设备配套 App 的同一晚、同一日期，检查起止时间及四种睡眠阶段。体征在“体征记录”查看；接入区显示设备日步数图和最近读取时间。
7. 再次连接，检查记录数量不翻倍、同一天步数为新累计值而不是累加、用户备注仍保留。凭证错误、空历史和不支持格式应显示实际提示。

找不到文件夹时，iOS 沙盒不允许 App 直接读取另一 App 的私有空间。当前没有实现云端取密钥，也没有完成备份取密钥工具。可继续使用“从系统健康读取”获取配套 App 确实写入的数据，来源不改成蓝牙。全新未绑定设备不能靠此功能跳过首次绑定。

## 处理规则

- 原扫描器仍用于搜索、记忆与选择；专用会话只使用选中设备的系统蓝牙 UUID，不按通用名称匹配另一台手环。
- 实现 V2 通道与上游 V1 兼容代码，但入口仅自动识别并接入 V2；不宣称所有型号均支持。
- 认证材料长度和设备 HMAC 通过后才处理健康命令；每次重连重新认证。凭证只存 `com.rocgrey.sleeptongshu.band-auth-v1` 钥匙串，设备专用、不同步云端；忘记设备可同时移除凭证，历史数据保留。
- 不执行时钟写入、监测开关、固件、通知或设备重置命令；文件传输按协议应答，但不发送删除设备历史的文件消费确认。仍需要真机核验固件行为。
- 读取最近 91 天范围内设备实际列出的睡眠、分钟活动、日汇总和手动体征文件。运动训练详情及 GPS 本次未接入，不能描述为所有运动项目均已支持。
- 完整分包及 CRC32 检查后才解析。未知版本原文件保存在 App 支持目录 `EncryptedBand/<蓝牙UUID>/<文件ID>.bin`，设备专用文件保护并排除系统备份；不自动上传，不包含绑定密钥。
- 只有明确的睡眠阶段区间生成 `SleepPayload`，标为设备来源。没有阶段的汇总不补造时间轴；未知阶段、非睡眠码及记录缺口显示为未记录，不能根据汇总比例生成阶段。有效实际心率/血氧/压力才进入体征记录，缺失不补零、不冒充睡眠平均值。
- 原文件信息、蓝牙 UUID、固定偏移时区和睡眠结束日存入可选 JSON 元数据，旧 SwiftData 表不变。按设备 UUID + 睡眠开始时间生成稳定记录 ID；同一开始时间的新结束记录更新原条，较短/覆盖更少的旧记录不覆盖较完整结果。不同开始时间或不同设备记录不擅自拼接，来源筛选由原有图表处理。
- 修改记录时保留独立备注，不覆盖其他来源。重复读取重新对账已读文件，但本次不实现设备删除事件；设备可能清理历史，不能因此删除本机已保存数据。
- 每日步数按设备与日期存本机日汇总，同日新累计值替换，不与其他设备或 HealthKit 相加。零步和没有记录区分；新增蓝牙日汇总不标为账号云端步数，不自动上报。
- 日常结果使用通用“设备”文案，蓝牙列表和已选目标保留真实名称方便识别。加密接入详情可分享，不包含认证密钥或认证包原文。

## 主要文件

- `STBandMiProtocol.swift`、`STBandMiProtocolV1.swift`：报文、CRC、认证及加密。
- `STBandBandLink.swift`：专用蓝牙会话、文件列表、分包、重试与状态。
- `STBandActivityFiles.swift`：历史文件解析，含睡眠 v6。
- `STBandKeyStore.swift`：主动选择文件夹的已有凭证解析，不联网获取。
- `EncryptedBandStore.swift`：独立 Keychain、SwiftData 导入、活动日缓存与体征保存。
- `EncryptedBandView.swift`：凭证导入、读取状态及步数图。
- `RingScanner.swift`、`MonitoringView.swift`、`SleepTongshuApp.swift`：复用原有入口与自动读取/保存。
- `PhoneSleepData.swift`、`SleepModels.swift`：可选来源元数据、设备时区与结束日。
- `WearableProbeView.swift`：BIO 等原有接入报告增加未完成提示，读取中不分享中间报告。
- `EncryptedBandTests.swift`、`EncryptedBandUITests.swift`：协议、导入、去重、缺失和凭证界面验证。
