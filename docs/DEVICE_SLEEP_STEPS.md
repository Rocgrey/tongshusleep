# 设备睡眠首页与步数统计

## 日常使用

- 在“监测与设备”连接已保存的设备，自动同步后返回“睡眠”。不用先点击“从系统健康读取”。
- 睡眠页默认优先选择“设备记录”，展示本机已保存的设备睡眠。仍可主动切换“系统健康”或“全部记录”；后台刷新不会强制改变手动选择。
- 没有设备睡眠、但已有设备体征或步数时，显示设备步数、最近体征和“暂无设备睡眠记录”。不拿示例睡眠填充设备页面。
- 系统健康为独立可选入口，在非系统来源下收起，展开即可使用原来的统一读取按钮；健康页原按钮保留。
- 步数摘要显示设备、记录日期及读取时间。点击摘要查看近 7/30 天统计，也可进入“趋势 → 步数 → 蓝牙设备”。
- “设备最近体征”展示各项实际数值及记录时间，可继续查看原有体征图表。这些单次记录不替代睡眠报告内的整晚平均值。

## 数据范围和规则

1. 睡眠继续从原有 SwiftData `SleepRecord` 读取，`.band` 是设备来源；不修改导入、备注、分期或健康权限逻辑。设备返回真实睡眠后，`@Query` 自动更新页面。设备列表中的连接成功本身不等于有睡眠记录。
2. BIO9 / 103 固件目前已验证的是实时当天累计步数、健康历史与睡眠原始输入。原始输入不是最终睡眠分期，因此不生成深睡、浅睡、REM、睡眠时长或参考分。原来已能读取睡眠结果的戒指及加密设备继续显示真实结果。
3. BIO 步数来自实时健康响应中实际存在的 `steps` 字段，记录接收时间。按当前已验证环境的北京时间（UTC+8）归日，与现有账号统计口径一致。出国或改变设备时区尚未验证，不声称能自动纠正设备时钟。
4. 新版本保存 `currentStepsReadAt`；兼容旧报告。旧报告只在开始与结束属于同一个北京时间日期时恢复，使用读取开始时间近似标注；跨午夜且没有精确时间的旧报告不导入。已有报告不改写为今天的数据。
5. 加密设备使用原有已校验的活动日汇总；沿用设备记录日期，界面单独标注。未知型号的实时步数不猜测其日归属。未取得日期或未解析的协议不补数。
6. 同设备同日累计值按读取时间更新，重复刷新不相加；允许后续设备修正较低的值；旧响应不能覆盖较新的记录。多设备分别查看，不相加，也不与系统健康或账号云端数据叠加。
7. 有效日均 = 有记录日期的累计 ÷ 有记录天数。真实 0 步参加日均；缺失日期留空。当天值只代表读取时的累计，可能继续增长。零散分钟包不拼成全天步数，避免把部分历史当成完整记录。
8. 设备日累计保存在 Application Support 的 `device-steps-v1.json`，采用原子写入和系统文件保护。它是本机设备记录，与独立按账号隔离的云端步数区分；不自动上传，不申请额外健康读取或写入权限。

## 修改文件

- `sleeptongshu/SleepDashboardView.swift`：来源选择、可选系统读取入口、设备摘要。
- `sleeptongshu/DeviceStepsStore.swift`：设备日步数模型、去重、本地保存及默认睡眠来源规则。
- `sleeptongshu/DeviceStepsView.swift`：当天步数、周期入口、最近体征。
- `sleeptongshu/AccountStepsView.swift`：在原有统计及图表中增加蓝牙设备来源。
- `sleeptongshu/SleepTongshuApp.swift`：接入设备响应和原有活动日汇总，向页面共享本地步数。
- `sleeptongshu/WearableProbeClient.swift`、`WearableProbeReport.swift`：确认 steps 字段存在后，原子发布累计值及精确读取时间。
- `sleeptongshuTests/DeviceStepsTests.swift`：重复读取、修正、乱序、跨日、真实 0、缺失、多设备、保存恢复、旧报告、分钟包与来源规则。
- `sleeptongshuUITests/DeviceDashboardUITests.swift`：无系统读取显示设备数据，周期图表，分期边界和来源选择。
- `sleeptongshuUITests/SystemSleepUITests.swift`：适配收起的系统读取入口。
- `sleeptongshuUITests/AccountUITests.swift`：适配统计来源的名称，保留原账号与系统步数检查。
