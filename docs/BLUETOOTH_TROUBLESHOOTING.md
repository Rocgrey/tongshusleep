# 蓝牙连接成功，为什么仍没有睡眠数据？

蓝牙连接是第一步。设备还需要开放数据服务、允许 App 读取，有时还需要厂商认证或专用命令。多数手环和戒指的历史睡眠并没有统一的蓝牙标准，不能靠扫描和连接自动获得深睡、REM、血氧或昨晚记录。

本版能够直接读取的公开标准数据为电量（180F/2A19）、型号（180A/2A24）、实时心率（180D/2A37）。这三项也需要设备确实提供相应特征和权限。已发现服务不代表已经读取成功，订阅心率成功也可能尚未收到一次测量。

**目前没有已完成的小米、华为或睡眠戒指历史睡眠适配器。仅有连接或诊断信息，不应显示“睡眠同步成功”。**

## 先在 App 中检查

1. Xcode 重新运行更新后的 App，打开“监测与设备 → 穿戴设备”，连接设备。
2. 查看“连接后的数据状态”。正在检查、等待设备数据、未发现标准特征、读取失败及超时会分别显示。首次检查或请求后约 12 秒仍没有结果会给出提示。
3. 点击“重新读取”再试。检查佩戴贴合、设备电量；如果厂商明确提供“心率广播”等设置，可在配套 App/设备内开启。不要把手机 App 的录音跟踪开关当成手环数据权限。
4. 展开“设备诊断”，查看系统返回的读取错误；可使用“分享设备诊断”导出文字，供型号适配时分析。报告包含设备广播名、型号、检查时间、服务/特征 UUID 与权限属性、错误信息，不包含原始录音或睡眠记录。
5. 配套 App 若占用连接，可以结束它当前的设备同步后重试；部分设备支持多连接，不能笼统认定一定冲突。无需先解绑、恢复出厂设置或抹掉历史数据。

“未发现标准特征”不等于设备没有传感器，可能表示设备使用私有数据协议。“读取失败”可能是权限、加密、设备状态或其他系统错误；以诊断中的实际错误为依据，不能仅凭连接状态认定是哪一种。

## 如何获得实际睡眠记录

### 路径一：通过 Apple 健康

先在设备配套 App 中正常同步睡眠。如果它支持向 Apple 健康写入睡眠，开启该项并确认 iPhone 的“健康 → 浏览 → 睡眠”已有记录。然后使用本项目的 `sleeptongshu-Health` scheme（需要允许 HealthKit 的签名配置）安装 App，在“监测与设备”连接 Apple 健康，授权读取并选择来源导入。

优点是可复用厂商已解码的数据；限制是厂商未必写入所有分期或体征。sleeptongshu 本身不要求小米账号，但配套 App 是否需要登录由厂商决定。普通 scheme 没启用 HealthKit，不能直接完成此路径。

### 路径二：适配具体型号

提供品牌、包装/设置中的完整型号、配套 App 名称、固件版本（若可查到），再结合蓝牙诊断确认设备开放哪些协议。优先使用官方 SDK 或公开文档，实现认证、历史数据请求、包解析、时间戳和单位映射，并与厂商报告逐晚比对。服务 UUID 本身不足以还原睡眠数据；设备有认证限制时，仍可能需要厂商账号或授权。

只有完成该型号适配并验证后，才能承诺直接同步。当前 `WearableSleepAdapter` 是扩展接口，尚不代表已支持某种戒指或手环。

### 根据配套 App 核对到的路径

- [小米运动健康 App Store](https://apps.apple.com/cn/app/id1493500777)：开发商 Beijing Xiaomi Co., Ltd，Bundle ID `com.xiaomi.miwatch.pro`。其官方说明明确包含向 Apple 健康传输“睡眠、心率”。因此优先在小米运动健康完成同步并允许写入健康，再在 iPhone 的“健康 → 浏览 → 睡眠 → 显示所有数据”确认有记录，最后由 sleeptongshu 健康版本读取。能传“睡眠”不代表一定包含全部 REM、深睡、血氧等明细，要以实际写入样本为准。App 内具体授权菜单可能随版本变化。
- [G Band App Store](https://apps.apple.com/cn/app/g-band/id6447599368)：开发商 Shenzhen Veepoo Technology Co., Ltd，Bundle ID `com.vpgband.app`。商店说明提到设备同步、睡眠质量和睡眠阶段，但本次读取的说明未明确承诺写入 Apple 健康；不能把其他 App（例如 H Band Lite）的 HealthKit 说明当成 G Band 的能力。可先检查“健康”中的 App 写入权限与实际记录。
- [Veepoo iOS SDK](https://github.com/HBandSDK/iOS_Ble_SDK) 及 [API 文档](https://github.com/HBandSDK/iOS_Ble_SDK/blob/master/iOS_sdk_source/doc/VeepooSDK%20iOS%20Api_en.md) 提供设备连接、验证状态、睡眠类型判断、普通/精确睡眠数据读取等接口。它是 G Band/Veepoo 方案的候选接入方向，尚未证明 L03 Ultra 支持该 SDK。读取准确睡眠还需设备本身具备该功能，不能凭 SDK API 名称生成所有阶段或体征。

以上资料于 2026-10-27 核对。用户随后提供固件版本及 G Band 导出的日志，完整分析见 [L03 Ultra 日志分析](GBAND_LOG_ANALYSIS.md)：895 条记录中有 869 条设备响应，两轮 DF 分包计数分别为 195、83 组；A7/B8 结构与 Veepoo 公开头文件吻合。日志没有服务/特征 UUID，也不足以可靠解码睡眠分期或体征，不能把它当作 sleeptongshu 已同步成功。

下一步使用本版“分享设备诊断”得到服务/特征信息，结合设备固件与厂商支持范围验证候选 SDK，再实现历史同步适配。当前没有将第三方 SDK 二进制引入项目，也没有验证该戒指是否能完全离线、无需厂商认证工作。

## 本次界面调整

底部从四项合并为三项：睡眠、监测与设备、趋势。手机监测、穿戴连接、Apple 健康读取归于“监测与设备”；本地备份、导入、清理和目标设置在该页上方的“本地数据与睡眠目标”。蓝牙扫描保留一处，原有睡眠数据库与备份格式不变。
