# BIO 数据读取与展示修复

日期：2026-11-11。当前实测对象：蓝牙名 BIO-7349，返回型号 BIO9，固件 103.0.0.11。其他固件不因名称相似而认定兼容。

## 已定位的问题

1. 设备确实返回电量原值 `100`，旧协议定义注释却是 `0...9`。旧代码按格数校验后丢弃，所以界面一直没有电量。现在 BIO9 / 103 系列按百分比显示，包括低于 10% 的值；其他型号仍使用旧格数规则，未知或越界值不猜测。
2. 原实现只收集最近 120 条健康记录用于报告，没有把历史心率、血氧等导入日常体征。现已按设备测量时间保存有效数据，启动时也可重新解析最近一份已完成报告，稳定 ID 保证重复读取不累加。
3. 设备通知已经开启时，再调用开启通知不保证有新的状态回调。重新检查设备可能停在准备阶段。现在检查到通知已开启就直接启动读取，超时检查同时匹配本次会话，旧会话不能中断新读取。
4. 体征页此前按最新测量选择设备，另一枚戒指较新的记录可能把页面默认指向戒指。由设备页进入时优先选择当前 BIO，用户仍能切换设备。

## 处理规则

- 时间适配限定为 BIO9 / 103 固件、报告时区字段 `80`，按设备 UTC+8 当地钟点转换为绝对时间。其他时区编码、未知型号或明显未来时间保留在报告，不用接收时间冒充测量时间；旅行后新的时区编码仍需验证。此次重新核对文档后，旧报告中看似未来八小时的时间已有明确解释，更新了先前报告的未确认结论。
- 有效平均心率优先，缺失时可使用设备血压测量的心率。血氧使用明确的平均字段；血压必须成对、范围有效且高压大于低压。
- SDNN 和 RMSSD 分开展示，保留厂家定义。日常 HRV 保存 SDNN 并标注毫秒，既有其他设备的未知单位不变。`-1000`、零或其他无效 HRV 不生成值，不通过过滤 RRI 编码推算 HRV。
- 压力仅对实际有效疲劳值采用文档公式 `100 - fatigue`。不使用示例代码的对数补算分支；报告中的真实零压力保留，日常体征仍沿用原有零压力过滤策略。
- 设备体温仅在完成标记为 1 且高位体温通过范围检查时出现在报告。呼吸率仅有有效字段时显示；不恢复隐藏的血糖、血脂和尿酸项目。
- 健康历史最多取最近 2880 个序号、每段最多 240 个；跨目录块读取。相邻传输段重叠一个端点以兼容边界差异，接收仍按类型加序号去重。心跳间隔最多 288 包，其他通道最多 8 包；总计最多 4096 包、8 MB。
- 最后一个序号缺失不会冒充完整读取。每段有总超时及无新包等待限制，停止后清理残帧，报告保存实际请求区间。没有宣称该上限一定覆盖完整两天或整夜。
- 当天累计步数来自实时摘要；分钟步数不与摘要相加，也不当作当天累计。体征按设备标识、指标、测量时间和来源更新，其他来源和其他设备保留。全部保存在本机，不自动上传或写回系统健康。
- 原始睡眠输入仍不是厂商睡眠结果。光学脉搏波、独立血氧/温度及三轴通道在既有实测中被拒绝，不虚构波形、分期或睡眠平均值。

新增测试覆盖百分比低电量与旧格数、当地时间、HRV 缩放、无效标记、未知时区、未来时间、重复导入和设备隔离、分段范围及旧报告兼容。界面使用明确标注的合成数据，覆盖小屏幕电量/图表和多个设备下优先显示当前 BIO。

最终验证：142 项单元测试中 141 项通过、1 项主动开启的线上写入测试跳过；4 项相关 UI 测试通过。包含真实报告本地回放、现有戒指/系统健康/账号测试回归和旧报告、体征图表的界面回归。模拟器测试构建及戒指工程真机签名构建通过；第二次修复版已覆盖安装并启动于 iPhone 15。用户已确认电量显示；通知启动和当前设备选择修复后的新一轮无线读取仍待用户结果，不把回放或界面测试当成已验证真实无线传输。

真机：结束配套 App 同步 → 在设备页连接已记忆的 BIO → 保持前台等待结束 → 查看设备电量、当天步数和最近体征 → 进入“体征记录”确认设备选中 BIO，再查看心率、血氧、血压和 HRV。报告的“本次有效体征”与“新增或更新”是不同数量；重复同步新增为零不代表没有记录。若失败，导出读取结束后的新报告，用型号、时间、请求区间和拒绝响应继续核验。

## 连接闪退修复（同日后续）

用户报告点击已记忆 BIO 后闪退。已从连接的 iPhone 只读取得系统崩溃报告；15:13:20 和 15:15:39 两次均为 `EXC_BREAKPOINT / SIGTRAP`，栈顶是 `WearableProbeProtocol.sampleRanges`。原始崩溃文件和设备日志仅保存在本机，不提交仓库。

原因是无符号整数计算 `high - take + 1`：完整读取从序号 0 开始的目录时，`take` 等于 `high + 1`，中间减法先发生下溢，来不及执行最后的加一。修正为 `high - (take - 1)`，保持相同区间含义，避免中间结果越界。

新增回归覆盖单条 `0...0`、实际大小的 `0...2828` 完整目录、41 种零起点目录及不同截取上限，原有最大序号与跨目录测试保留。19 项历史/协议测试通过，戒指工程真机签名构建通过；修复版已覆盖安装并启动，数据库保留。最新版新一轮 BLE 历史读取结果仍待真机复测，不以安装或单元测试代替设备读取成功。

崩溃前的新报告已实际收到型号 BIO9、固件、电量 100 和当天累计 4221 步，但还未进入历史接收。因此这次没有新增历史体征，不能把崩溃后的空报告解释为设备没有数据。
